# 各家导出格式完整性对照

> 基于 0.8.0 的适配器实现 · 2026-11-23
> 目标：说明“能导入什么、会丢什么”，不宣称官方兼容。

## 1. 会话内容

| 格式              | 分支       | 思考 | 工具/搜索          | 系统提示词 | 附件                 | 组附加信息 | 主要损失                                               |
| ----------------- | ---------- | ---- | ------------------ | ---------- | -------------------- | ---------- | ------------------------------------------------------ |
| DeepSeek 官方 ZIP | 完整树     | 有   | 工具步骤、搜索来源 | 有         | 图片原件、文件元数据 | 无         | 最少；是当前最完整格式                                 |
| ChatGPT ZIP/JSON  | 仅当前分支 | 无   | `search_result_groups` 来源可展示；无工具步骤 | 有         | 文件元数据，无原件   | 记忆摘要   | 工具块、引用、附件原件、其他分支；GenUI 仅静态标题/说明；assistant 文档/画布正文可能未导出（官方 viewer 也缺失） |
| Claude ZIP/JSON   | 可重建     | 有   | 无                 | 有         | 文件元数据，无原件   | 项目、记忆 | 工具块、附件原件；部分会话导出缺回复正文               |
| Gemini Takeout    | 无         | 无   | 无                 | 无         | 图片文件名           | 无         | 活动日志非完整会话；带引用段落可能被 Google 替换为 `.` |
| z.ai / OpenWebUI  | 当前分支   | 无   | 无                 | 视导出     | 无                   | 无         | 正文可能缺失（厂商导出限制）                           |
| turn_history      | 无         | 无   | 无                 | 有         | 无                   | 无         | 样本身份未验证，仅 best-effort                         |
| 通用 JSON         | 无         | 无   | 无                 | 视字段     | 无                   | 无         | 仅识别常见 `messages` 结构                             |

## 1.1 Token 用量

| 格式                          | Token 用量                              |
| ----------------------------- | --------------------------------------- |
| DeepSeek                      | 有，进入统计面板                        |
| ChatGPT                       | 当前样本没有 usage/token 字段，无法汇总 |
| Claude                        | 当前样本没有 usage/token 字段，无法汇总 |
| Gemini / z.ai / 通用          | 没有可用的 token 字段                   |
| 附件中的 `token`/`price` 字段 | 与模型用量无关，不纳入统计              |

ChatGPT 的模型字段主要是会话级 `default_model_slug`，以及消息级
`metadata.model_slug` / `metadata.resolved_model_slug`。

## 2. Gemini 的特殊损失

Gemini Takeout 的 `MyActivity.json` 是**活动日志**：

- 同一 `details[].url` 的记录按时间聚合为一个会话
- 用户提示来自 activity `title`，不是独立字段
- 助手回复来自 `safeHtmlItem[].html`
- 带内联引用的段落，Google 可能只保留 `.` 占位；`MyActivity.html` 同样如此
- 图片只有文件名；`.dat`/图片原件未导入
- 没有分支、工具、引用结构、完整系统提示词

这不是解析器遗漏，是导出源本身不完整。

## 3. 附件策略

| 来源                    | 当前行为                                        |
| ----------------------- | ----------------------------------------------- |
| DeepSeek                | 图片原件写入 IndexedDB，支持去重和删除清理      |
| ChatGPT                 | 附件只保留文件名、类型、大小；`.dat` 原件未导入 |
| Claude                  | 附件只保留文件名/类型；无原件                   |
| Gemini                  | 图片只保留文件名；不导入 Takeout 图片           |
| z.ai / OpenWebUI / 通用 | 不导入附件                                      |

浏览器存储不是备份；附件原件是否入库必须考虑配额和驱逐风险。

## 4. 导出能力

| 导出格式           | 保留内容                                              | 有损项                                               |
| ------------------ | ----------------------------------------------------- | ---------------------------------------------------- |
| DeepSeek 兼容 ZIP  | DeepSeek 原生字段、适用时的图片原件                   | 非 DeepSeek 来源会丢分支/工具/引用；未实测官方客户端 |
| 对话浏览器扩展 ZIP | 分组、系统提示词、摘要、引用/思考状态                 | 不是完整备份；附件原件仍依赖本地存储                 |
| Claude JSON        | 当前可见分支、摘要、思考、引用、文件元数据、parent 链 | 仅当前分支；附件无原件                               |
| HTML / Markdown    | 所选轮次的可读内容                                    | 不保留结构化元数据、附件原件                         |

## 5. 结论

- 想要最完整：优先 DeepSeek 原生 ZIP
- ChatGPT / Claude：适合迁移正文和主要结构，不能承诺附件和工具链完整
- Gemini：只能做“活动日志级”归档，正文缺失要明确告知
- 所有外部格式都不能当作官方客户端兼容格式
